# 仓库整理与推送说明（2026-09-10）

本轮汇总此前尚未提交的工作，将代码与网站、实验与审计快照、项目文档分别组织为提交。首次整理在已有工作分支完成；随后按用户要求，将全部整理结果快进合入并推送至 **`origin/main`**，本地也切换到 **`main`**，后续交付以主分支为准。远端 main 原有提交全部保留，不改写历史。

整理前本地 HEAD 与当时工作分支的远端一致；待处理的是工作区改动，而非一批已经提交但尚未推送的提交。

发布范围：

- 已选模型、方向排序及历史模型研究的实现、配置、测试和可复现入口。
- React/TypeScript 网站、Python 数据服务、登录、SPR 最终表、对照展示和实验结果回填功能。
- 多方向 TxGNN/OT/EC-KG、亲和证据整理及评估、384 设计与 FDA 对照修订的配套脚本。
- 当前 384 候选及 112 个另计参考对照的交付表、修订前记录、紧凑研究结果和磁盘清理执行结论。
- 项目现状、研究演化、评估边界、实验交付和维护文档，以及已整理的汇报图件。

原忽略规则对部分输出目录仅取消了目录忽略，没有继续排除后代文件，导致约 3.4 万个运行产物出现在待提交列表，其中有 417 MiB 的 checkpoint。现改为 `outputs/.gitignore` 逐文件白名单；模型权重、数据库、特征数组、完整运行缓存、账号文件、前端依赖与构建目录留在本地。

脚本继续采用受控白名单。本轮补齐网站、实验设计、疾病证据、亲和评估和清理入口，以及静态检索到的本地源码依赖；未将全部历史一次性脚本无条件加入仓库。当前推送数据是明确列出的研究交付和审计快照，不包含实际湿实验回填数据库。

新增 `.gitattributes` 保持 `outputs` 审计与冻结文件的原始字节，不进行换行转换，以免破坏发布在 manifest 中的 SHA256。Markdown 的显式换行与生成 SVG 的路径格式保留；源码中的多余行尾空格和空白行已整理。

- 前端 `npm run build`：通过 TypeScript 检查及 Vite 构建。
- 已暂存 Python 文件解析：无语法错误；静态检查未发现缺失的本地 Python 模块依赖。
- 提交差异格式检查通过。
- 提交范围中未发现 checkpoint、NumPy 特征数组、SQLite 数据库、`node_modules` 或实际实验回填目录；没有超过 10 MiB 的新增/修改文件。
- 对暂存内容执行常见密钥、私钥及凭据字面量模式检查，没有发现疑似凭据。此项是模式检查，不是穷尽性安全证明。
