# palinova 国际对标与升级建议

更新：2026-09-10。阶段依据：团队正在采购、配液或准备蛋白，尚不能据此宣称已有湿实验验证结果。本次完成网站品牌改名与升级评估；以下新增能力是建议，不代表已经上线。

## 1. 当前判断

palinova 已具备候选排名、药物与靶点档案、疾病关联、结构口袋、来源追踪、SPR 设计及结果录入。下一阶段最有价值的定位是：**可追溯、可前瞻验证的老药新靶点研究平台**。

网站当前选择的 ReTargetMap 部署版本为 2026-09-06，结合 DrugCLIP、Morgan、ESM2，并展示其他模型比较。网站品牌与模型名称分别管理；网站改名不改变模型、实验编号或历史文件的科学身份。

本轮核查范围为网站当前实现、最终实验表及其清单，不是对全部训练历史的复现。不能据此声称国际领先或模型性能已获实验验证。

## 2. 国际对标：分别借鉴什么

| 对标对象 | 公开能力/结论 | 对 palinova 的具体启发 |
| --- | --- | --- |
| Open Targets | 将靶点优先级拆成临床先例、可成药性、可执行性、安全性 | 保留结合排名，另设采购/构建可行性、疾病机制和安全性维度，不将所有证据混成一个“成功概率” |
| Benchling | 关联注册实体、库存样本及实验结果 | 增加轻量样本台账，让每条结果能回到采购实体、批号、构建和方法版本；无需先复制整个商业 LIMS |
| TxGNN | 面向药物—疾病的零样本重定位，并提供可解释路径 | 疾病假设单独呈现支持和矛盾证据，继续与药物—蛋白结合预测区分 |
| DrugCLIP | 以蛋白口袋—分子对比表征实现虚拟筛选 | 现有结构分支已有相关能力；升级重点应是实际构建与口袋是否对应，并用同一候选空间评价增益 |
| 严格虚拟筛选基准 | 不同诱饵集下模型排序可变化；姿态准确性、物理合理性和筛选富集不是同一指标 | 同时报告任务定义、候选集合、结构来源及公平基线，不能只用漂亮结构或单项分数证明有效 |

来源：[Open Targets 官方优先级框架](https://platform-docs.opentargets.org/web-interface/target-prioritisation)、[Benchling 官方库存说明](https://www.benchling.com/inventory)、[TxGNN 原始论文](https://www.nature.com/articles/s41591-024-03233-x)、[DrugCLIP 原始论文](https://arxiv.org/abs/2310.06367)、[Nature Machine Intelligence 虚拟筛选基准](https://www.nature.com/articles/s42256-025-00993-0)。Benchling 仅作工作流参照，供应商功能介绍不能证明提高命中率。以上是有针对性的对标，不是穷尽全部国际平台的排行榜。

## 3. 优先级与验收标准

### P0：首批上机前——采购、构建、对照闭环

在 SPR 页面增加“实验准备”页签，按靶点/批次组织，显示待采购、已到货、已配液、蛋白待确认、可上机等状态。状态需有负责人、时间与依据；不能仅凭模型排名自动放行。

最低数据模型：

- 药物实体：内部 ID、结构标识、盐型/立体化学、供应商、货号、批号、纯度及 COA 附件。
- 配液样本：样本 ID、母液来源、浓度与单位、溶剂、配液时间、存放位置、经手人。
- 蛋白实体：UniProt、物种、isoform、残基边界、突变、标签、供应商、批号、序列或序列哈希。
- 执行计划：设计版本、experiment_id、pair_id、药物样本 ID、蛋白批次 ID、拟用对照、方法版本、确认人。

验收：首批计划每条都能定位唯一药物样本、蛋白批次与对照；构建不匹配有明确原因和处理记录。暂缺信息应显示“待确认”，不能填推测值。当前 112 项对照应按实际开工批次逐项确认，不将整张设计清单直接改成“实验中”。

### P0：结果产生前——冻结前瞻评价

保存本轮候选、对照、分数、排名、筛选条件、模型/数据版本及清单哈希；由实验负责人确定响应检出、QC 合格、重复确认、结合确认等判定规则和排除规则，并锁定规则版本。

当前候选经过排名与人工/疾病证据筛选，因此这批结果首先衡量“本轮联合选择流程”。若要证明模型优于其他策略，需要在同一可实验候选空间预先制定比较方案。模型在同一批候选上的事后排名比较，可作条件性分析，不能自动证明其全空间命中率更高。

验收：结果到来前已有评价方案；报告分别展示计划数、实际检测数、QC 合格数、检出数、重复确认数和未判定数；参考对照单独统计，不混入新候选命中率。更改方案有时间和原因，不覆盖原版本。

### P1：首批回传——原始数据与人工复核

沿用已有结果录入模块，新增原始曲线/拟合报告的文件标识、SHA256、方法版本、重复实验关联、对照 QC、复核人和结论版本。原始大文件可留在服务器受控目录，通过受鉴权接口访问。

结果状态建议为“待复核→需补充/已确认”；更正创建新版本并指向原记录。既有上传归属不是完整审核制度。未检出响应、QC 失败、无法判定分别保存，不能统一作为训练负样本。

验收：任意结果可追溯原始文件与样本；页面明确区分响应检出、结合确认及后续功能证据；所有更正可回溯，审核权限由后端校验。

### P1：对外展示——项目进度与证据层级

首页增加来自真实台账的采购/准备/上机/复核进度；阶段无记录时显示待登记。保留原配色和紧凑排版。提供中英文显示、统一术语表及可分享的实验摘要；目标疾病中文名保留标准 ID 与英文原名。

展示版适合精简为候选假设、关键证据、实验阶段和下一步；详细原始记录继续折叠。展示账号只读，实验账号可录入，审核账号可签认。建议为实验文件和 SQLite 制定定时备份、恢复演练、进程自动恢复与外网健康检查。

验收：展示页的每个计数都有明确分母和更新时间；只读账号不能通过直接调用 API 写入；备份能在隔离目录恢复，不以“存在备份文件”代替恢复验证。

### P2：获得首批可信结果后——模型评价与实验反馈

先按靶点家族、药物骨架相似度、结构来源、模型一致性、疾病证据强弱分层，定位错误发生在哪类候选；用同一预算、候选空间和标签口径比较 ReTargetMap、DrugCLIP、DTIAM、ConPLex 与简单相似性基线。缺失评分保留缺失并报告覆盖率。

离线实验补充时间切分、药物骨架/蛋白相似性隔离、重复样本及预训练重叠审计。结构亲和力领域已有针对相似性泄漏的专门数据重组研究，可借鉴其审计思路，不能直接套用其指标作为本项目成绩。[Leak Proof PDBBind 原始研究](https://arxiv.org/abs/2308.09639)

前瞻报告给出固定定义下的确认率与置信区间；同药或同靶点记录并非完全独立，区间估计需考虑聚类。只有高排名候选的样本不足以校准全空间概率。扩大探索或设置比较组需另行安排预算，不擅自改动已采购方案。

验收：固定测试批不用于调参；新模型回放能与冻结旧模型比较；不得把本轮拟合后的模型在同一批结果上的表现称作前瞻验证。

### P2：结合确认后——机制与疾病转化

为确认候选补充选择性、作用方向、细胞靶点作用证据、疾病相关体系及暴露可达性等后续证据，由湿实验团队确定验证方法。把“可能结合”“功能效应”“疾病假设支持”分别建模，逐级累积。

这是结合当前研究目标与国际证据框架提出的路线判断，不是本次已经验证的疗效结论。后续主动学习可综合预测不确定性、候选多样性、实验成本和构建可行性，待可信数据量足够后再评估是否有真实增益。

## 4. 建议实施顺序

| 阶段 | 交付 | 主责 |
| --- | --- | --- |
| 现在至首批上机前 | 准备台账、首批样本/构建/对照确认；冻结前瞻评价方案 | 湿实验负责人 + 平台开发 + 建模负责人 |
| 首批回传时 | 原始数据关联、复核与更正、真实进度看板、备份恢复 | 湿实验复核人 + 平台开发 |
| 首批复核后 | 分层误差报告、公平基线比较、下一批选择建议 | 建模负责人 + 湿实验团队 |
| 后续独立批次 | 验证新版模型的增益；补充机制与选择性证据 | 双方共同 |

首个开发任务建议选择“实验准备台账”，它直接服务眼下采购与配液，也为后续结果的解释打基础。功能应扩展现有 SPR 页面与结果模块，而不是另建彼此断开的系统。
